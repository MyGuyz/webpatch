# แผน: เว็บแปะแพตช์ภาษาไทย (webpatch) — Frontend + Backend ฟรี 100%

## Context

Repo `MyGuyz/webpatch` ตอนนี้มีแค่ `personal.md` (บันทึก role "พี่กวน") ยังไม่มีโค้ดเว็บ

โจทย์: ทำเว็บแนวเดียวกับ **นอนแปล** (nonplae.com) และ **Memory_Card_TH** (retrogame.synology.me) — เว็บแจกแพตช์แปลไทยสำหรับเกมย้อนยุค จุดขายคือผู้ใช้เลือกไฟล์เกมต้นฉบับของตัวเอง กดปุ่มเดียว แล้วได้ไฟล์เกมภาษาไทยกลับไปเล่น โดย**ไฟล์เกมไม่เคยถูกอัปโหลดขึ้นเซิร์ฟเวอร์** (แปะในเบราว์เซอร์ล้วนๆ)

ความต้องการที่ผู้ใช้ยืนยันระหว่างการซักถาม:
- มี **backend จริง** เพื่อ "เพิ่มเกม ลบเกม ได้สะดวก" ไม่ต้องแก้ไฟล์ JSON ผ่าน git
- **ฟรีทั้งหมด ไม่ต้องผูกบัตรเครดิต**
- ทำงานบน GitHub เป็นหลัก
- รองรับหลายเครื่องเล่น รวมถึงเครื่องใหม่ๆ ในอนาคต

ข้อจำกัดที่ค้นพบระหว่างออกแบบ (ทดสอบจริงแล้ว ไม่ได้เดา):
- **GitHub Pages โฮสต์ backend ไม่ได้** → ต้องย้ายที่โฮสต์ แต่โค้ดยังอยู่ GitHub และ deploy อัตโนมัติเหมือนเดิม
- **ไฟล์ใน GitHub Releases ไม่ส่ง CORS header** → เบราว์เซอร์อ่านไม่ได้ ต้องมีตัวกลาง
- **`raw.githubusercontent.com` ส่ง `access-control-allow-origin: *`** แต่เพดานไฟล์ 100MB แข็ง → ใช้กับแพตช์ใหญ่ไม่ได้
- ทั้งสองที่รองรับ `Accept-Ranges: bytes` → ทยอยโหลดทีละท่อนได้

## สถาปัตยกรรมที่ตกลงแล้ว

| ส่วน | ใช้อะไร | ทำไม |
|---|---|---|
| โค้ด + CI | **GitHub** | ตามที่ผู้ใช้ต้องการ push แล้ว deploy เอง |
| หน้าเว็บ + API | **Astro (SSR) บน Cloudflare Pages** | ฟรีไม่ต้องบัตร, SSR ทำให้เกมใหม่ขึ้นทันทีและ Google เก็บ index ได้, ส่ง JS น้อย |
| ฐานข้อมูล + Auth | **Supabase** | ฟรี, มี Postgres + ระบบ login ครบ, มีหน้าแก้ข้อมูลสำรองให้ใช้ตอนฉุกเฉิน |
| ไฟล์แพตช์ | **GitHub Releases** | ฟรีสนิท ไฟล์ถึง 2GB คนโหลดไม่จำกัด มีระบบเวอร์ชันในตัว |
| รูปปก / รูปแนบบั๊ก | **Supabase Storage** | ไฟล์เล็ก อยู่ในโควต้า 1GB สบาย |
| ตัวกลาง CORS | **Astro API route** (รันเป็น Cloudflare Worker) | แก้ปัญหา CORS ของ GitHub Releases โดยไม่เพิ่มเจ้าใหม่ |

**จุดที่ต้องระวังและออกแบบรองรับไว้แล้ว:** Cloudflare ฟรีจำกัด **ขนาดข้อมูลขาเข้า** 100MB ต่อครั้ง แต่**ไม่จำกัดขาออก** แปลว่า:
- ให้ผู้ใช้**ดาวน์โหลด**แพตช์ 500MB ผ่านตัวกลาง → ผ่านฉลุย (แค่ส่งต่อสาย ไม่ต้องอมไฟล์ไว้)
- แอดมิน**อัปโหลด**แพตช์ 500MB ผ่านตัวกลาง → **ไม่ผ่าน** จึงต้องแยกทางเดินตามข้อ ADR-005

## ADR ที่จะบันทึกลง `docs/adr/`

**ADR-001 — แยกที่โฮสต์ออกจาก GitHub Pages**
ต้องมี backend แต่ GitHub Pages เสิร์ฟไฟล์นิ่งอย่างเดียว → ย้ายไป Cloudflare Pages ซึ่งฟรี ไม่ต้องบัตร และ deploy จาก GitHub ได้ตรงๆ โค้ดและไฟล์แพตช์ยังอยู่บน GitHub ทั้งหมด

**ADR-002 — Supabase เป็นฐานข้อมูลและระบบ login**
ผู้ใช้ต้องการจัดการเกมสะดวก ทางเลือกคือ Supabase กับ Cloudflare D1 เลือก Supabase เพราะมีระบบ login มาให้พร้อม และมีหน้าแก้ข้อมูลสำรองให้ใช้ได้ทันทีตั้งแต่วันแรก ไม่ต้องรอหน้า Admin เสร็จ

**ADR-003 — ไฟล์แพตช์อยู่บน GitHub Releases ไม่ใช่ Supabase Storage**
Supabase ฟรีให้ที่เก็บ 1GB และขาออกเดือนละ 5GB ซึ่งแพตช์ PS1 ตัวเดียวขนาด 100MB มีคนโหลด 50 คนก็หมดโควต้าทั้งเดือน GitHub Releases ฟรี ไฟล์ถึง 2GB คนโหลดไม่จำกัด

**ADR-004 — มีตัวกลาง (proxy) คั่นระหว่างเว็บกับ GitHub Releases**
ทดสอบแล้วพบว่าไฟล์ใน GitHub Releases ไม่มี `access-control-allow-origin` เบราว์เซอร์จึงห้าม JS อ่านเนื้อไฟล์ ทางแก้คือ Astro API route ดึงไฟล์มาส่งต่อพร้อมติด CORS header ให้ (ส่งแบบ stream ไม่อมไฟล์ไว้ในหน่วยความจำ) ทางเลือกที่ตัดทิ้ง: Cloudflare R2 (ต้องผูกบัตร), เก็บใน repo (ติดเพดาน 100MB), ให้ผู้ใช้เลือก 2 ไฟล์เอง (เสียจุดขายกดปุ่มเดียวจบ)

**ADR-005 — หน้า Admin อัปไฟล์เล็กผ่านฟอร์ม ไฟล์ใหญ่วางลิงก์**
GitHub token ห้ามอยู่ในหน้าเว็บเด็ดขาด จึงต้องส่งผ่านตัวกลางที่เก็บ token ไว้ฝั่งเซิร์ฟเวอร์ แต่ตัวกลางรับข้อมูลขาเข้าได้แค่ 100MB จึงแยกเป็น 2 ทาง: ไฟล์ ≤100MB อัปผ่านฟอร์มได้เลย, ไฟล์ใหญ่กว่านั้นแอดมินลากขึ้นหน้า release ของ GitHub เองแล้ววางลิงก์ในฟอร์ม (เพิ่มเกมสัปดาห์ละครั้ง ความไม่สะดวกจึงรับได้ แลกกับความปลอดภัยและไม่มีเพดาน)

**ADR-006 — เขียนตัวแปะแพตช์เอง ไม่ใช้ไลบรารีภายนอก**
รองรับ 3 รูปแบบ: `.ips`, `.bps`, `.ppf` ทั้งสามมี spec สาธารณะและโครงสร้างไม่ซับซ้อน เขียนเองรวมไม่กี่ร้อยบรรทัด เลี่ยงการดึงไลบรารี GPL-3.0 (เช่น rom-patcher-js) ที่จะผูกเงื่อนไขลิขสิทธิ์ทั้ง repo ออกแบบเป็น registry `{ '.ips': …, '.bps': …, '.ppf': … }` เพิ่มรูปแบบใหม่ทีหลังได้โดยไม่แตะโค้ดเดิม

**ADR-007 — ไฟล์เกมของผู้ใช้ห้ามออกจากเครื่องเด็ดขาด**
การแปะแพตช์ทำในเบราว์เซอร์ทั้งหมด เราแจกเฉพาะแพตช์ ผู้ใช้ต้องมีไฟล์เกมต้นฉบับเอง เป็นทั้งจุดยืนด้านกฎหมายและเป็นการประหยัด bandwidth ต้องเขียนบอกผู้ใช้ให้ชัดบนหน้าเว็บ (เว็บตัวอย่างทั้งสองแห่งก็เขียนไว้เด่นชัดเหมือนกัน)

**ADR-008 — รายงานบั๊กเก็บใน Supabase ไม่ใช่ GitHub Issues**
คนเล่นเกมทั่วไปส่วนใหญ่ไม่มีบัญชี GitHub และ Issue เป็นสาธารณะ เก็บใน Supabase แล้วดูรวมในหน้า Admin สะดวกกว่าและใช้ระบบที่มีอยู่แล้ว

## Glossary (จะบันทึกลง `docs/glossary.md`)

| คำ | ความหมายในโปรเจกต์นี้ |
|---|---|
| **แพตช์ (Patch)** | ไฟล์ส่วนต่างที่เอาไปทับไฟล์เกมต้นฉบับแล้วได้เกมภาษาไทย — เป็น**สิ่งเดียวที่เว็บนี้แจก** |
| **ไฟล์เกมต้นฉบับ (Source ROM/ISO)** | ไฟล์เกมที่ผู้ใช้ต้องมีเอง เว็บไม่แจกและไม่รับอัปโหลด |
| **แปะแพตช์ (Apply)** | การเอาแพตช์ทับไฟล์ต้นฉบับ ทำในเบราว์เซอร์ของผู้ใช้เท่านั้น |
| **SHA1 ต้นฉบับ** | ลายนิ้วมือของไฟล์เกมรุ่นที่แพตช์รองรับ ใช้ตรวจก่อนแปะว่าผู้ใช้ใช้ไฟล์ถูกรุ่นไหม |
| **ตัวกลาง (Patch Proxy)** | Astro API route ที่ดึงไฟล์จาก GitHub Releases มาส่งต่อพร้อม CORS header |
| **ขั้นความคืบหน้า (Progress Stage)** | สถานะงานแปล 5 ขั้น: แกะรอม → ดึงคำแปล → แปลแล้ว → ฝังคำแปล → ตรวจสอบบัค |

## แบ่งเป็น 4 เฟส

**เฟส 1 — หน้าแรกขึ้นจริง** *(ที่ผู้ใช้เลือกเป็น MVP)*
วางโครง Astro + เชื่อม Cloudflare Pages + สร้างตารางใน Supabase + หน้าแรก (ประกาศ, ผลงานล่าสุด, เมนูล่าง) + ใส่ข้อมูลเกมแรกผ่านหน้าแก้ข้อมูลของ Supabase ไปก่อน
→ จบเฟสนี้ได้เว็บที่เปิดดูได้จริงจาก URL สาธารณะ

**เฟส 2 — หน้าแปะแพตช์** *(แกนหลักของเว็บ)*
ตัวแปะ `.ips`/`.bps`/`.ppf` + ตรวจ SHA1 + ตัวกลาง CORS + หน้าเลือกเครื่อง/เลือกเกม + กล่อง log + ปุ่มดาวน์โหลด

**เฟส 3 — หน้า Admin**
ระบบ login + ฟอร์มเพิ่ม/แก้/ลบเกม + อัปแพตช์ขึ้น GitHub Releases (ไฟล์ ≤100MB) + อัปรูปปก

**เฟส 4 — หน้ากำลังทำอยู่ + หน้าแจ้งบั๊ก**
การ์ด roadmap พร้อมแถบความคืบหน้า 5 ขั้น + ฟอร์มแจ้งบั๊กพร้อมแนบรูป + หน้ารวมบั๊กใน Admin

## Verification

**เฟส 1:** `npm run dev` เปิดหน้าแรกได้, ข้อมูลเกมดึงจาก Supabase จริง, deploy ขึ้น Cloudflare Pages แล้วเปิด URL จริงได้บนมือถือ

**เฟส 2 (สำคัญที่สุด):**
- ทำไฟล์ทดสอบเล็กๆ คู่ ต้นฉบับ + แพตช์ + ผลลัพธ์ที่ถูกต้อง สำหรับทั้ง 3 รูปแบบ แล้วเทียบ byte ต่อ byte ว่าตัวแปะของเราให้ผลตรงเป๊ะ
- ทดสอบว่าเลือกไฟล์ผิดรุ่นแล้วขึ้นเตือน SHA1 ไม่ตรง และ**ไม่ยอมแปะให้**
- ทดสอบตัวกลาง CORS ด้วยไฟล์จริงจาก GitHub Releases จากโดเมนของเว็บ
- ทดสอบไฟล์ใหญ่ (แผ่น PS1 ~700MB) บนคอมและมือถือ ดูว่าแรมไม่ระเบิดและเซฟไฟล์ได้

**เฟส 3:** เพิ่มเกมใหม่ผ่านฟอร์มแล้วเช็คว่าขึ้นหน้าเว็บทันที, ทดสอบว่าคนไม่ได้ login เรียก API อัปไฟล์แล้วโดนปฏิเสธ

**เฟส 4:** ส่งรายงานบั๊กพร้อมรูปแล้วเช็คว่าเข้า Supabase และโผล่ในหน้า Admin

ทุกเฟสทดสอบบนมือถือเป็นหลัก (mobile-first ตาม `personal.md`)

## สิ่งที่ยังไม่ได้ตัดสินใจ (ไม่บล็อกการเริ่มงาน)

- **ธีมและหน้าตา** — ยังไม่ได้เลือกระหว่างสไตล์ retro อบอุ่นแบบนอนแปล กับ dark theme แบบ Memory_Card_TH จะเคาะตอนเริ่มเฟส 1
- **ชื่อเว็บและโดเมน** — ตอนนี้ใช้ URL ฟรีของ Cloudflare Pages ไปก่อน ผูกโดเมนตัวเองทีหลังได้
- **การเซฟไฟล์ใหญ่บน Firefox/Safari** — เบราว์เซอร์สองตัวนี้ไม่มี API เขียนไฟล์ลงดิสก์โดยตรง ต้องอมไฟล์ไว้ในแรมก่อนเซฟ ซึ่งไฟล์ระดับ GB อาจไม่รอด จะรู้ผลจริงตอนทดสอบเฟส 2 แล้วค่อยตัดสินใจว่าจะแนะนำให้ใช้ Chrome หรือหาทางอื่น
