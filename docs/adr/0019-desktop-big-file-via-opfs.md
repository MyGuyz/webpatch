# ไฟล์ใหญ่มากบนคอมพิวเตอร์: แปะลง OPFS ให้เสร็จก่อน แล้วค่อยดาวน์โหลดแบบปกติ

## ปัญหา

แปะ God of War II (ISO 8.5GB) บน Chrome Windows ผ่าน `showSaveFilePicker()` (ADR-017) แล้ว
`writable.close()` โยน `InvalidStateError` ทุกครั้ง — ไฟล์ `<ชื่อ>.crswap` มีเนื้อครบและ SHA-1
ถูกต้อง แต่ Chrome ย้ายมันไปเป็นไฟล์จริงไม่สำเร็จ ผู้ใช้เห็นไฟล์ 0 ไบต์กับ error ภาษาอังกฤษ

สิ่งที่พิสูจน์แล้ว (2026-11-02):
- ทำซ้ำได้บนเครื่องทดสอบด้วย Chrome จริง: แปะเสร็จ 100% แล้ว close() พังหลังผ่านไปราว 55 วินาที
  (Chrome แฮชไฟล์ทั้งก้อนเพื่อตรวจ Safe Browsing ก่อนย้าย) เหลือ .crswap ค้าง
- ไม่ใช่โปรแกรมสแกนไวรัส/ระบบไฟล์: ทำขั้นเดียวกันเองด้วย Node (เขียน 8.5GB → อ่านแฮชทั้งไฟล์ →
  เปลี่ยนชื่อทับไฟล์ 0 ไบต์ทันที) สำเร็จทุกครั้ง — ปัญหาอยู่ในขั้นย้ายไฟล์ของ Chrome เอง
  (`base::Move` ล้มแล้วถูกแปลงเป็น `FILE_ERROR_FAILED` → `InvalidStateError`) หน้าเว็บแก้ไม่ได้

## ทางที่ลองแล้วไม่ใช้: ดาวน์โหลดแบบสตรีมผ่าน service worker

ส่งผลลัพธ์ทีละก้อนเข้าตัวจัดการดาวน์โหลดผ่าน service worker (แบบ StreamSaver.js) ใช้ได้ถ้า Chrome
ไม่ถามที่บันทึกไฟล์ แต่เจ้าของเว็บตั้ง "ถามที่บันทึกไฟล์ทุกครั้ง" ไว้ แล้วเจอทั้ง "ดาวน์โหลดถูกยกเลิก
กลางทาง" และ "ขึ้นว่าแปะเสร็จแต่ไฟล์ใช้ไม่ได้" — Chrome รับข้อมูลลงไฟล์ชั่วคราวไปแล้วระหว่างกล่อง
"บันทึกเป็น" ยังเปิด แล้วค่อยย้ายตามที่ผู้ใช้เลือก ข้อมูลจาก service worker ขอซ้ำไม่ได้ ถ้า Chrome
ต้องเริ่มอ่านใหม่ก็พัง จึงเลิกใช้

## การตัดสินใจ

คอมพิวเตอร์ + แพตช์ PPF + ไฟล์ใหญ่กว่า `VERY_BIG_FILE_BYTES` (1.5GB):

1. แปะลงไฟล์ใน **OPFS** (พื้นที่เก็บไฟล์ส่วนตัวของเว็บ) ผ่าน `createSyncAccessHandle()` ใน worker
   (`src/patcher/opfs-patch-worker.js`) — เขียนตรงตำแหน่งในไฟล์เลย ไม่มี .crswap ไม่มีขั้นย้ายไฟล์
2. เช็คว่าไฟล์ผลลัพธ์ใหญ่เท่าต้นฉบับ (PPF ไม่เปลี่ยนขนาด) — ไม่เท่าก็ไม่ยอมให้ดาวน์โหลด
3. ปุ่มเปลี่ยนเป็น "ดาวน์โหลดไฟล์ภาษาไทย" แบบเดียวกับไฟล์เล็ก กดแล้วดาวน์โหลดจาก Blob URL ของไฟล์
   ใน OPFS — ไฟล์อยู่บนดิสก์ ไม่ได้อยู่ในแรม และเป็นการดาวน์โหลดปกติที่เบราว์เซอร์อ่านซ้ำได้
   จะถามที่บันทึกหรือไม่ก็จัดการเองได้

ต้องมีที่ว่างในไดรฟ์ที่เก็บโปรไฟล์ Chrome (ปกติ C:) อย่างน้อยเท่าขนาดไฟล์เกม — ไม่พอ
(`navigator.storage.estimate()`) ถอยไปใช้ `showSaveFilePicker()` ตาม ADR-017 แทน
ไฟล์ใน OPFS ถูกลบตอนกดแปะรอบถัดไป หรือตอนเปิดหน้าแปะแล้วไฟล์เก่าเกิน 30 นาที

**มือถือไม่เปลี่ยน** — Android ยังใช้ `showSaveFilePicker()` ตาม ADR-017 ซึ่งใช้งานได้จริงอยู่แล้ว

## ทดสอบอย่างไร

`e2e/big-download.mjs` — Playwright + Chrome จริง (โปรไฟล์ปกติ) แปะ God of War II จาก ISO จริง
8.5GB แล้วกดดาวน์โหลด ผล (2026-11-02): แปะลง OPFS 67 วินาที ดาวน์โหลด 51 วินาที ไฟล์ที่ได้
SHA-1 `cd620d48d73bb4932d5f8d982afbfd220a82b0e6` ตรงผลลัพธ์ที่ถูกต้องเป๊ะ

ข้อสังเกตตอนทดสอบ:
- Chrome โหมดไม่ระบุตัวตน (และ context ปกติของ Playwright) เก็บ OPFS ในแรม เขียนไฟล์ 8.5GB ได้แค่
  ราว 2GB โดยไม่มี error — จึงต้องมีข้อ 2 (เช็คขนาด) และ e2e ต้องใช้ `launchPersistentContext`
- โหมด "ถามที่บันทึกไฟล์ทุกครั้ง" ยังทดสอบอัตโนมัติไม่ได้ (ต้องกดกล่อง Save As ของ Windows —
  สคริปต์กดแทนคนแล้วผลเชื่อถือไม่ได้) เจ้าของเว็บต้องลองเองบนเครื่องจริง
