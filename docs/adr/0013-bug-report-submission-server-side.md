# ย้ายการส่งรายงานบั๊กทั้งก้อนไปทำฝั่งเซิร์ฟเวอร์

ตอนตรวจโค้ดพบว่า `/api/bug-report-guard` (ADR-010) เป็นแค่คำขอความร่วมมือ — เบราว์เซอร์เป็น
คนตัดสินใจเองว่าจะยิงคำขอไปเช็คก่อนไหม และต่อให้เช็คแล้วโดนบล็อก เบราว์เซอร์ก็ยังเลือกเขียน
ข้อมูลจริงต่อได้อยู่ดี เพราะ `bug_reports` insert และ `bug-reports` storage upload เปิดให้
`anon`/`authenticated` ยิงตรงจาก Supabase JS SDK ได้เสมอ (RLS `with check (true)`)

คนที่เปิด DevTools ดูค่า `window.__SUPABASE__` (URL + anon key อยู่ในหน้าเว็บอยู่แล้วเป็น public
โดยดีไซน์) แล้วเรียก SDK ตรงๆ ข้าม `/api/bug-report-guard` ไปเลย จะส่งรายงานปลอม/อัปโหลดไฟล์
(สูงสุด 30MB/ไฟล์) ได้ไม่จำกัดจำนวนครั้ง เสี่ยงกินโควตา Storage/แบนด์วิดท์ของ Supabase จนเว็บ
ทั้งเว็บกระทบ และท่วมคิวแอดมินจนหารายงานจริงไม่เจอ

## การตัดสินใจ

ย้ายทุกขั้นตอนที่ "เขียนข้อมูลจริง" (ตรวจฟอร์ม, กันสแปม, อัปโหลดไฟล์แนบ, insert แถว) ไปทำที่
`/api/bug-report-submit` ฝั่งเซิร์ฟเวอร์ทั้งหมด ใช้ `SUPABASE_SERVICE_ROLE_KEY` ซึ่งไม่มีทาง
ถูกข้ามจากฝั่งเบราว์เซอร์ได้ (ไม่เคยส่งไปให้ browser เห็นเลย) แล้วปิด policy insert ของ
`anon`/`authenticated` บน `bug_reports` และ `storage.objects` (bucket `bug-reports`) ทิ้ง
(migration `0012_bug_reports_server_only_writes.sql`) เบราว์เซอร์จึงไม่มีทางเขียนข้อมูลสองตาราง
นี้ได้อีกเลยไม่ว่าจะข้าม UI ของเว็บอย่างไร

**ผลที่ตามมา:** `SUPABASE_SERVICE_ROLE_KEY` (และแนะนำให้ตั้ง `IP_HASH_SALT` ด้วย) กลายเป็น
ค่าที่**ต้องตั้งเป็น Secret ใน Cloudflare** ไม่ใช่ตัวเลือกเสริมเหมือนเดิมอีกต่อไป — ถ้าไม่ตั้ง
ฟอร์มแจ้งบั๊กจะขึ้น "เซิร์ฟเวอร์ยังไม่ได้ตั้งค่า" ทุกครั้ง (ดู `docs/setup.md`)

การย่อรูปในเบราว์เซอร์ก่อนอัปโหลด (ADR-010) ยังทำที่ฝั่งเบราว์เซอร์เหมือนเดิม เพราะเป็นแค่การ
ลดขนาดไฟล์ก่อนส่ง ไม่ใช่ขั้นตอนที่ต้องเชื่อใจได้ — เซิร์ฟเวอร์ยังตรวจชนิด/ขนาดไฟล์ซ้ำเองอีกชั้น
ก่อนอัปโหลดจริงอยู่ดี
