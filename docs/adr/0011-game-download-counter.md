# นับจำนวนคนแปะแพตช์ต่อเกม กันปั่นตัวเลขด้วย hash IP รายวัน

เพิ่มคอลัมน์ `games.download_count` นับทุกครั้งที่ `/api/patch-file/[id]` เสิร์ฟไฟล์แพตช์สำเร็จ
(จุดเดียวที่เซิร์ฟเวอร์เห็นการ "โหลดแพตช์ไปใช้" จริง — การแปะเองและดาวน์โหลดผลลัพธ์เกิดฝั่ง
เบราว์เซอร์ทั้งหมด เซิร์ฟเวอร์มองไม่เห็น)

**ทำไมนับที่ตรงนี้ ไม่นับตอนกดปุ่ม "แปะแพตช์" ในหน้าเว็บ:** กดปุ่มแล้วไม่ได้แปลว่าโหลดไฟล์
สำเร็จเสมอไป (เช่น เน็ตหลุดกลางทาง) นับที่ endpoint ที่เสิร์ฟไฟล์จริงตรงกว่า

**การป้องกันคนปั่นตัวเลข:** ใช้รูปแบบเดียวกับ `bug_report_rate_limit` (ADR-010) — ตาราง
`game_download_log` เก็บ hash ของ IP ผสม salt (ย้อนกลับเป็น IP จริงไม่ได้) จำกัด**1 คน
1 เกม 1 ครั้งต่อวัน** ด้วย primary key `(ip_hash, game_id, day)` ถ้า insert ชนกัน (นับไปแล้ว
วันนี้) จะข้ามไม่บวกตัวนับซ้ำ — ป้องกันคนกดโหลดซ้ำๆ ปั่นตัวเลขให้ดูเยอะกว่าความจริง โดยไม่ต้อง
ให้ผู้ใช้ login หรือเก็บข้อมูลส่วนตัวใดๆ

**บวกตัวนับผ่าน SQL function `increment_game_download_count`** แทนที่จะ select แล้ว update
จาก JS เพื่อกันแข่งกันอ่าน-เขียนถ้ามีคนโหลดพร้อมกันพอดี

**ใช้ secret ชุดเดียวกับ ADR-010** (`SUPABASE_SERVICE_ROLE_KEY`, `IP_HASH_SALT`) ไม่ต้องตั้งค่า
เพิ่ม เพราะตั้งไว้แล้วตอนทำระบบกันสแปมฟอร์มแจ้งบั๊ก — ถ้ายังไม่ได้ตั้งค่า ระบบจะข้ามการนับไปเงียบๆ
ไม่บล็อกการโหลดแพตช์จริง (เหมือน ADR-010)
