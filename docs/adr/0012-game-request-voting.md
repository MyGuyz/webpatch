# โหวตเกมที่อยากให้แปลต่อไป ใช้แพทเทิร์นกันสแปมชุดเดียวกับ ADR-010/011

เพิ่มตาราง `game_requests` (คำขอเกม) แยกจากตาราง `games` — คำขอเป็นแค่ "ชื่อเกมที่มีคนอยากได้"
ยังไม่ใช่เกมที่ตัดสินใจทำจริง จึงไม่ผูกกับ schema ของ `games` ที่มีฟิลด์เกี่ยวกับแพตช์/ความคืบหน้า
เต็มไปหมด ทีมสามารถ "เลื่อนขั้น" คำขอไปเป็นแถวใน `games` เองด้วยมือเมื่อตัดสินใจเริ่มทำจริง

**แนะนำเกมใหม่:** เปิดให้ใครก็ insert ได้ตรงๆ เหมือนฟอร์มแจ้งบั๊ก (มี honeypot กันบอทพื้นฐาน)
เพราะความเสี่ยงต่ำ — อย่างแย่สุดคือมีชื่อเกมแปลกๆ โผล่มาในลิสต์ ซึ่งแอดมินลบเองได้เลย
ไม่คุ้มที่จะสร้างระบบกันสแปมหนักๆ สำหรับจุดนี้

**โหวต:** ต่างจากแนะนำเกม เพราะโหวตซ้ำได้ง่ายและกระทบอันดับ (spam 1 คนกดรัวๆ ก็ปั่นอันดับได้)
จึงต้องผ่าน API route (`/api/vote-game-request`) ที่กันด้วย hash ของ IP **แพทเทิร์นเดียวกับ
ตัวนับดาวน์โหลด (ADR-011)** เป๊ะ — ตาราง `game_request_votes` เก็บ `(ip_hash, request_id)`
เป็น primary key, บวกคะแนนแบบอะตอมมิกผ่าน SQL function, ใช้ secret ชุดเดียวกัน
(`SUPABASE_SERVICE_ROLE_KEY`, `IP_HASH_SALT`) ไม่ต้องตั้งค่าเพิ่มเติมใดๆ เลย

**ฝั่งเบราว์เซอร์จำเพิ่มอีกชั้นด้วย localStorage** ว่าเคยโหวตอันไหนไปแล้ว เพื่อปิดปุ่มไม่ให้กดซ้ำ
ทันทีโดยไม่ต้องรอเซิร์ฟเวอร์ตอบ — เป็นแค่ UX ช่วยให้ดูลื่นขึ้น การกันซ้ำจริงยังอยู่ที่เซิร์ฟเวอร์
เสมอ (ล้าง localStorage หรือเปลี่ยนเครื่องก็ยังโหวตซ้ำไม่ได้ เพราะเช็คจาก IP ฝั่งเซิร์ฟเวอร์)
