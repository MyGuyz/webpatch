# ไฟล์ใหญ่มากบนคอมพิวเตอร์: เลือกโฟลเดอร์ก่อน แล้วแปะเขียนลงไฟล์ในโฟลเดอร์นั้นตรงๆ

แทนที่ ADR-019 (OPFS + ดาวน์โหลดปกติ) สำหรับ Chrome/Edge บนคอมพิวเตอร์

## ปัญหา

เจ้าของเว็บแปะ RE4 (4.4GB) ด้วยทาง ADR-019 แล้วหน้าเว็บขึ้น "แปะแพตช์เสร็จแล้ว!" แต่แถบดาวน์โหลด
ของ Chrome ขึ้น **"Failed - System busy"** ได้ไฟล์ `Unconfirmed NNN.crdownload` ขนาดครบที่ Chrome
เปลี่ยนชื่อไม่สำเร็จ เจ้าของอยากได้แบบ "เลือกที่เก็บก่อน แล้วค่อยแปะ เสร็จแล้วได้ไฟล์ชื่อถูกต้อง"

## สิ่งที่ทดสอบแล้ว (2026-11-02, Chrome 155 Windows, คุม Chrome ทดสอบแยกโปรไฟล์ผ่าน DevTools protocol)

**ดาวน์โหลดปกติ (Blob URL) ไฟล์หลาย GB พังใน Chrome จริง** ไม่ว่าลงไดรฟ์ไหน:
- 100MB, 1.5GB ลง G: ผ่าน · 4.0GB ลง G: พัง · 4.3GB ลง F: (SSD) พัง — ค้างเป็น
  `Unconfirmed NNN.crdownload` ขนาดครบ สถานะ "Failed - System busy"
- ผล "ดาวน์โหลด 8.5GB ผ่าน" ใน ADR-019 มาจากการรันผ่าน Playwright ซึ่งรับไฟล์ดาวน์โหลดแทน Chrome
  เอง (ข้ามขั้นตรวจไฟล์ก่อนเปลี่ยนชื่อของ Chrome) — **ไม่ได้แทนผลของ Chrome ที่ผู้ใช้ใช้จริง**

**`FileSystemWritableFileStream.close()` พังเมื่อไฟล์ใหญ่กว่า 4GB** ไม่ว่าลงไดรฟ์ไหน:
- 4,000,000,000 ไบต์ ผ่าน · 4,300,000,000 ไบต์ พัง (`InvalidStateError`) ทั้งบน F: (SSD) และ G: (HDD)
- ไฟล์ `<ชื่อ>.crswap` เนื้อครบถูกต้องค้างอยู่ ไฟล์ชื่อจริงเหลือ 0 ไบต์
- **แต่สั่งเปลี่ยนชื่อ .crswap เป็นชื่อจริงซ้ำจากหน้าเว็บอีกครั้งหลังจากนั้น 5 วินาทีผ่าน** (ครั้งแรกทันที
  หลัง close() พังยังพัง ครั้งถัดไปผ่าน) ได้ไฟล์ SHA-1 ตรงกับต้นฉบับเป๊ะ
- เขียน + เปลี่ยนชื่อด้วย Node (ทั้งชื่อ node.exe และก๊อปเป็นชื่อ chrome.exe) ไม่เคยพังสักครั้ง —
  ต้นเหตุอยู่ในขั้นตอนตรวจไฟล์ก่อนเปลี่ยนชื่อของ Chrome เอง (Chrome ไม่ log อะไรให้ดู)

**ปัญหาผูกกับนามสกุล .iso:** ไฟล์ 4.3GB ชื่อ `.bin` หรือ `.img` close() ผ่านทันที (25–30 วินาที เทียบกับ
.iso ที่ใช้ 60+ วินาทีแล้วพัง) และสั่ง `move()` เปลี่ยนชื่อไฟล์ .bin ที่ปิดเรียบร้อยแล้วเป็น .iso ผ่าน

**วนเปลี่ยนชื่อ .crswap → .iso ซ้ำใช้ไม่ได้กับไฟล์ 8.5GB:** ลองแล้ว 12 รอบบน G: พังทุกรอบ (แต่ละรอบ Chrome
อ่านไฟล์ทั้งก้อนใหม่ราว 1 นาที ระหว่างนั้น Chrome เองถือไฟล์ไว้ตลอด) แม้ 4.3GB บน F: รอบที่ 2 จะผ่าน

**ย้ายไฟล์จาก OPFS ไปโฟลเดอร์จริงด้วย `move()` ไม่ได้** (`InvalidModificationError`) จึงใช้ OPFS เป็น
ทางผ่านไม่ได้

## การตัดสินใจ

Chrome/Edge บนคอมพิวเตอร์ + แพตช์ PPF + ไฟล์ใหญ่กว่า 1.5GB (`useFolderSaveFor` ใน `patch-ui.js`):

1. กดแปะ → `showDirectoryPicker({ mode: 'readwrite' })` ให้เลือก**โฟลเดอร์**ก่อน (Chrome ถามอนุญาต
   แก้ไขไฟล์อีกชั้น)
2. เขียนเป็น `<ชื่อเกม>_TH.bin` ในโฟลเดอร์นั้น (ชื่อซ้ำเติม " (2)" ไม่เขียนทับของเดิม) แปะแบบสตรีม
   (`streamApplyPPF`) ลง writable ของไฟล์นั้นตรงๆ — ไม่ต้องมีที่ว่างใน C: เพิ่ม
3. `close()` (ชื่อ .bin ผ่าน) — ถ้ายังพัง หา `.crswap` ที่**ขนาดเท่าต้นฉบับ**แล้วเปลี่ยนชื่อเองซ้ำ
4. `move()` เปลี่ยนชื่อ .bin → `<ชื่อเกม>_TH.iso` ลองครั้งเดียว (แต่ละครั้ง Chrome อ่านไฟล์ทั้งก้อนใหม่ ไฟล์ 8.5GB บน HDD ราว 1 นาที และ e2e พบว่า 8.5GB ลอง 3 ครั้งก็ไม่ผ่าน) ไม่ผ่านก็**คงไฟล์ .bin ไว้** (เนื้อไฟล์
   เหมือนกันทุกไบต์ PCSX2 เปิดได้) ป๊อปอัปแปะเสร็จบอกผู้ใช้
5. เช็คขนาดไฟล์สุดท้ายต้องเท่าต้นฉบับ (PPF ไม่เปลี่ยนขนาด) แล้วจึงขึ้นป๊อปอัป "แปะเสร็จ"
   (`src/lib/save-folder-stream.js`)

ต้องเป็นโฟลเดอร์ ไม่ใช่กล่อง Save As แบบไฟล์ เพราะ handle ของไฟล์เดียวเข้าถึงไฟล์ .crswap ข้างๆ
ไม่ได้ จึงเปลี่ยนชื่อซ้ำเองไม่ได้

ทางอื่นคงไว้:
- คอมพิวเตอร์ที่ไม่มี `showDirectoryPicker` (Firefox/Safari): OPFS + ดาวน์โหลด ตาม ADR-019
- มือถือ Android: `showSaveFilePicker` ตาม ADR-017 (ไม่มี `showDirectoryPicker`)
- iPhone: ไม่มี API เขียนไฟล์ลงเครื่องเลย ยังแปะไฟล์ใหญ่ระดับ PS2 ไม่ได้

## ข้อจำกัด

- Chrome ไม่ให้เลือกรากไดรฟ์ (G:\) หรือโฟลเดอร์ Downloads/Desktop ตรงๆ ต้องเลือกโฟลเดอร์ย่อย
  (ข้อความใน `bigFileNoteText` บอกไว้)
- ขั้นตรวจไฟล์ของ Chrome ตอน close() อ่านไฟล์ทั้งก้อนอีกรอบ — บน HDD ไฟล์ 8GB ใช้เวลาหลายนาที

## ทดสอบอย่างไร

- `save-folder-stream.test.js`: โฟลเดอร์ปลอมจำลอง close() พัง/เปลี่ยนชื่อพังหลายครั้ง/.crswap
  ไม่ครบ (ต้องไม่เปลี่ยนชื่อไฟล์ไม่ครบให้ดูเหมือนสำเร็จ)/เปลี่ยนเป็น .iso ไม่ผ่าน (ต้องได้ .bin)
- e2e ด้วย Chrome จริง: GoW2 8.5GB ลงโฟลเดอร์บน G: ผ่านหน้าเว็บจริง (กล่องเลือกโฟลเดอร์กดด้วย
  สคริปต์ส่งข้อความถึงหน้าต่างโดยตรง) — ผลอยู่ในหัวข้อถัดไป
