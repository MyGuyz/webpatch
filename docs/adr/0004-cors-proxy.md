# ADR-004 — มีตัวกลางคั่นระหว่างเว็บกับ GitHub Releases

**สถานะ:** ตกลงแล้ว · 2026-08-20

## บริบท
เว็บต้องอ่านเนื้อไฟล์แพตช์เข้ามาในเบราว์เซอร์เพื่อเอาไปแปะกับไฟล์เกมของผู้ใช้ (ตาม ADR-007 การแปะทำฝั่งผู้ใช้ทั้งหมด)

## หลักฐานจากการทดสอบจริง
ทดสอบด้วย `curl` ส่ง `Origin` header ไปยัง release asset จริง:

| ปลายทาง | `access-control-allow-origin` | `Accept-Ranges` | เพดานไฟล์ |
|---|---|---|---|
| GitHub Releases | **ไม่มี** | `bytes` | 2GB |
| `raw.githubusercontent.com` | `*` | `bytes` | 100MB (แข็ง) |

→ เบราว์เซอร์จะบล็อกไม่ให้ JS อ่านไฟล์จาก GitHub Releases

## ทางเลือกที่พิจารณา
- **ย้ายไป `raw.githubusercontent.com`** — CORS ผ่าน แต่ติดเพดาน 100MB ใช้กับแพตช์ใหญ่ไม่ได้ และทำให้ repo บวมด้วยไฟล์ไบนารี
- **ย้ายไป Cloudflare R2** — CORS คุมได้เอง แต่ต้องผูกบัตรเครดิต ขัดเงื่อนไข
- **ให้ผู้ใช้โหลดแพตช์เองแล้วเลือก 2 ไฟล์** — ไม่ต้องมีตัวกลาง แต่ทิ้งจุดขาย "กดปุ่มเดียวจบ" ซึ่งเป็นเหตุผลที่เว็บนี้มีอยู่
- **มีตัวกลางส่งต่อพร้อมติด CORS ให้** ← เลือกข้อนี้

## การตัดสินใจ
สร้าง Astro API route (`/api/patch-file/[gameId]`) ที่รันบน Cloudflare ทำหน้าที่ดึงไฟล์จาก GitHub Releases แล้ว**ส่งต่อแบบ stream** พร้อมติด CORS header ให้

## ข้อจำกัดที่ต้องรู้ (สำคัญ)
Cloudflare ฟรีจำกัด **ข้อมูลขาเข้า 100MB ต่อคำขอ** แต่ **ไม่จำกัดขาออก** แปลว่า:
- ส่งไฟล์ 500MB ให้ผู้ใช้ดาวน์โหลด → **ผ่าน** เพราะเป็นการส่งต่อสาย ไม่ได้อมไฟล์ไว้
- รับไฟล์ 500MB จากแอดมินอัปโหลด → **ไม่ผ่าน** จึงต้องมี ADR-005 แยกต่างหาก

## ผลที่ตามมา
- ต้องส่งแบบ stream เท่านั้น ห้ามอ่านไฟล์ทั้งก้อนเข้าหน่วยความจำก่อนส่ง
- ควรส่ง `Accept-Ranges` ต่อไปด้วย เพื่อให้อนาคตทยอยโหลดทีละท่อนได้
