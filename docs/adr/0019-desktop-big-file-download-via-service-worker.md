# ไฟล์ใหญ่มากบนคอมพิวเตอร์: ดาวน์โหลดแบบสตรีมผ่าน service worker แทน showSaveFilePicker

แปะ God of War II (ISO 8.5GB) บน Chrome Windows ผ่านทาง `showSaveFilePicker()` (ADR-017) แล้ว
`writable.close()` โยน `InvalidStateError` ("...state had changed since it was read from disk")
ทุกครั้ง (เจ้าของเว็บลอง 4 รอบ) — เนื้อไฟล์ถูกเขียนครบใน `<ชื่อ>.crswap` แล้ว (SHA-1 ตรงผลลัพธ์
ที่ถูกต้องเป๊ะ) แต่ Chrome ย้าย .crswap ไปเป็นไฟล์จริงไม่สำเร็จ ผู้ใช้เห็นแค่ข้อความ error ภาษา
อังกฤษ ไฟล์ปลายทาง 0 ไบต์ และนึกว่าแปะไม่สำเร็จ

ตัดเรื่องโปรแกรมสแกนไวรัสออกแล้ว: เขียนไฟล์ 8.5GB แล้วเปลี่ยนชื่อทันทีด้วย Node ในโฟลเดอร์เดียวกัน
สำเร็จใน 219ms ปัญหาอยู่ในขั้น close() ของ Chrome เอง (แฮชไฟล์ทั้งก้อนเพื่อตรวจ Safe Browsing
แล้วค่อยย้าย) ซึ่งหน้าเว็บแก้ไม่ได้ และทดสอบอัตโนมัติไม่ได้เพราะต้องผ่านกล่อง Save As ระดับ OS

## การตัดสินใจ

คอมพิวเตอร์ + แพตช์ PPF + ไฟล์ใหญ่กว่า `VERY_BIG_FILE_BYTES` (1.5GB) → **ส่งผลลัพธ์ทีละก้อนเข้า
ตัวจัดการดาวน์โหลดของเบราว์เซอร์ผ่าน service worker** (`src/lib/download-stream.js` +
`public/sw.js`) — วิธีเดียวกับไลบรารี StreamSaver.js:

1. หน้าเว็บสร้าง `TransformStream` ส่งฝั่งอ่านให้ service worker ทาง `postMessage` (transferable
   streams) แล้วรอ service worker ตอบรับ
2. เปิด iframe ซ่อนไปที่ `/__download/<id>` — service worker ตอบด้วยฝั่งอ่านเป็นไฟล์แนบ พร้อม
   `Content-Length` = ขนาดไฟล์ต้นฉบับ (PPF ไม่เปลี่ยนขนาดไฟล์)
3. `streamApplyPPF` เขียนลงฝั่งเขียนทีละก้อน 16MB โดยรอ `writer.ready` ก่อนทุกก้อน (backpressure —
   แรมใช้แค่ไม่กี่ก้อน)
4. ส่ง ping ให้ service worker ทุก 10 วินาที ไม่งั้นเบราว์เซอร์ปิดมันทิ้งหลังว่าง 30 วินาที
   แล้วสตรีมที่วิ่งผ่านมันจะขาดกลางทาง

ตัวจัดการดาวน์โหลดถูกออกแบบมาสำหรับไฟล์หลาย GB อยู่แล้ว ไฟล์ไปอยู่ใน Downloads เหมือนทางปกติ
และไม่ต้องมีกล่อง Save As ก่อนแปะ

**ถอยกลับทางเดิมอัตโนมัติ** ถ้า service worker ยังไม่คุมหน้าเว็บ หรือไม่ตอบภายใน 1.5 วินาที
(เช่นยังเป็นตัวเก่าที่ไม่รู้จักข้อความนี้) → ใช้ `showSaveFilePicker()` ตาม ADR-017 แทน
ถ้า close() ของทางนั้นพังอีก หน้าเว็บจะบอกวิธีเปลี่ยนชื่อไฟล์ .crswap เอง

**มือถือไม่เปลี่ยน** — Android ยังใช้ `showSaveFilePicker()` ตาม ADR-017 ซึ่งใช้งานได้จริงอยู่แล้ว

## ทดสอบอย่างไร

`e2e/big-download.mjs` — Playwright + Chrome จริง เปิดหน้าแปะ God of War II ใน dev server,
เลือก ISO จริง 8.5GB, ตอบคำขอแพตช์ด้วย PPF จริง, กดแปะ แล้วเทียบ SHA-1 ของไฟล์ที่ดาวน์โหลดได้
ผล (2026-11-02): ตรวจไฟล์ 110 วินาที แปะ+ดาวน์โหลด 70 วินาที ป๊อปอัปแปะเสร็จขึ้น และไฟล์ที่ได้
SHA-1 `cd620d48d73bb4932d5f8d982afbfd220a82b0e6` ตรงผลลัพธ์ที่ถูกต้องเป๊ะ

ข้อสังเกตตอนทดสอบ: ถ้าตั้ง `downloadsPath` ของ Playwright ไปไดรฟ์อื่น (G:) ดาวน์โหลดทุกแบบถูก
ยกเลิกที่ 0 ไบต์ — เป็นเรื่องของตัวทดสอบเอง ไม่ใช่หน้าเว็บ (ใช้โฟลเดอร์ค่าเริ่มต้นแล้วผ่าน)
