# กันสแปมฟอร์มแจ้งบั๊กด้วย hash ของ IP + ย่อรูปในเบราว์เซอร์ก่อนอัปโหลด

> **⚠️ ส่วนของ `/api/bug-report-guard` ในเอกสารนี้ถูกแทนที่แล้ว — ดู ADR-013**
> ตอนนั้น API route นี้เป็นแค่ตัวเช็คที่เบราว์เซอร์เลือกเรียกเองก่อนเขียนข้อมูลตรงเข้า Supabase
> ด้วยกุญแจ anon ทำให้ข้ามได้ง่าย ตอนนี้ทั้งการเช็คและการเขียนข้อมูลย้ายไปรวมอยู่ที่
> `/api/bug-report-submit` ฝั่งเซิร์ฟเวอร์ทั้งหมดแล้ว ส่วนที่ยังใช้ได้จริงจากหน้านี้คือเหตุผล
> เรื่อง hash ของ IP กับตาราง `bug_report_rate_limit` (ยังเหมือนเดิมทุกอย่าง) และเรื่องย่อรูป
> ในเบราว์เซอร์ก่อนอัปโหลด (ยังทำที่เดิม)

ฟอร์มแจ้งบั๊กเดิมไม่มีการกันสแปมใด ๆ นอกจาก honeypot field (ดู ADR-009) — บอทที่ข้าม honeypot ได้
จะส่งได้ไม่จำกัดจำนวนครั้ง เพิ่ม**การจำกัดจำนวนครั้งต่อเครือข่าย** ผ่าน API route ใหม่
(เดิมชื่อ `/api/bug-report-guard` — ดูหมายเหตุด้านบน) ที่รัน**ก่อน**การอัปโหลดไฟล์และบันทึกลง
`bug_reports` ทุกครั้ง

**ทำไมเก็บ hash ไม่เก็บ IP จริง:** IP ถือเป็นข้อมูลส่วนบุคคลตามหลัก privacy-by-design ของเว็บนี้
(ดู ADR อื่นที่เน้นไม่เก็บข้อมูลเกินจำเป็น) จึง hash ด้วย SHA-256 ผสม salt ลับก่อนเก็บ
ย้อนกลับเป็น IP จริงไม่ได้แม้จะเข้าถึงฐานข้อมูลได้ตรง ๆ

**ทำไมใช้ตาราง Supabase แทน Cloudflare KV:** โปรเจกต์ใช้ Supabase อยู่แล้วและเจ้าของเว็บคุ้นเคยกับ
ขั้นตอน "รัน migration ใน Supabase dashboard" จากงานก่อนหน้านี้ ส่วน KV ต้องสร้าง namespace
และผูก binding ใหม่ใน Cloudflare ซึ่งเป็นขั้นตอนที่ไม่คุ้นเคยกว่า แลกมาด้วยการ query ช้ากว่า KV
เล็กน้อย แต่ปริมาณการแจ้งบั๊กของเว็บนี้ต่ำมากจนไม่กระทบ

**ผลต่อ schema/infra:** ตารางใหม่ `bug_report_rate_limit` (migration `0004`) ไม่มี RLS policy
ใด ๆ เลย เข้าถึงได้เฉพาะ service role key เท่านั้น API route จึงต้องมี env var ใหม่ 2 ตัวที่
**ต้องตั้งค่าเป็น Secret ใน Cloudflare** ไม่ใช่ตัวแปรทั่วไป: `SUPABASE_SERVICE_ROLE_KEY`
(จาก Supabase dashboard) และ `IP_HASH_SALT` (ค่าสุ่มอะไรก็ได้ที่ไม่มีใครเดาได้) — ตอนนั้น
(ก่อน ADR-013) ถ้ายังไม่ตั้งค่า ระบบจะปล่อยผ่านทุกคำขอ ไม่บล็อกการแจ้งบั๊กจริง เพราะเบราว์เซอร์
ยังเขียนข้อมูลตรงได้อยู่ดี — ตอนนี้ `SUPABASE_SERVICE_ROLE_KEY` จำเป็นเสมอ (ไม่งั้นแจ้งบั๊กไม่ได้
เลย) ส่วน `IP_HASH_SALT` ยังเป็นตัวเลือกเสริมเหมือนเดิม (ไม่ตั้ง = ข้ามแค่ขั้นกันสแปม)

**ย่อรูปในเบราว์เซอร์ก่อนอัปโหลด:** เพิ่ม `compress-image.js` วาดรูปลง Canvas แล้ว re-encode
เป็น JPEG ลดคุณภาพวนจนกว่าจะเหลือไม่เกิน ~1.5MB (เพดานต้นฉบับยังคง 15MB เท่าที่ยอมรับไฟล์เข้ามา)
ลดภาระโควต้า Supabase Storage ที่จำกัดไว้ (ดู ADR-009) และให้คนเน็ตช้าอัปโหลดได้เร็วขึ้น
ไม่ทำกับวิดีโอเพราะบีบอัดวิดีโอในเบราว์เซอร์ซับซ้อนและหนักเกินคุ้มสำหรับสเกลของเว็บนี้
