# ADR-006 — เขียนตัวแปะแพตช์เอง ไม่ใช้ไลบรารีภายนอก

**สถานะ:** ตกลงแล้ว · 2026-08-20

## บริบท
ต้องรองรับรูปแบบแพตช์ที่ใช้จริง 3 แบบ: `.ips`, `.bps`, `.ppf` (ยืนยันแล้วว่า**ไม่มี** `.xdelta`)

## การตัดสินใจ
เขียนตัวแปะเองทั้ง 3 รูปแบบ วางไว้ที่ `src/patcher/` โดยทำเป็น registry ที่จับคู่นามสกุลไฟล์กับตัวแปะ

## เหตุผล
- ทั้งสามรูปแบบมี spec สาธารณะและโครงสร้างตรงไปตรงมา รวมกันไม่กี่ร้อยบรรทัด
- **เลี่ยงเงื่อนไขลิขสิทธิ์** — ไลบรารีสำเร็จรูปที่นิยม (rom-patcher-js) เป็น GPL-3.0 ซึ่งจะผูกเงื่อนไขมาถึงโค้ดทั้ง repo
- คุมพฤติกรรมเรื่องหน่วยความจำเองได้ ซึ่งจำเป็นกับไฟล์ใหญ่

## ผลพลอยได้เรื่องหน่วยความจำ
การที่ไม่มี `.xdelta` ทำให้กำแพงเรื่องแรมหายไปเกือบหมด:
- **IPS และ PPF** เป็นแบบ "เขียนทับเป็นจุดๆ" (offset + ข้อมูล) → ทยอยเขียนทีละท่อนได้ ไม่ต้องยัดแผ่น PS1 700MB เข้าแรมทั้งก้อน
- **BPS** ต้องใช้แรมมากกว่าเพราะเป็นการสร้างไฟล์ใหม่จากต้นฉบับ แต่ใช้กับ ROM เล็ก (SNES/GBA) อยู่แล้วจึงไม่ชนเพดาน

## การรองรับเครื่องใหม่ในอนาคต
ออกแบบเป็น registry ตั้งแต่ต้น การเพิ่มรูปแบบใหม่ (เช่น `.xdelta` ถ้าวันหนึ่งต้องใช้) ทำได้โดยเพิ่มไฟล์โมดูลใหม่ 1 ไฟล์ กับอีก 1 บรรทัดใน registry โดยไม่ต้องแตะโค้ดเดิม

## ยืนยันกับไฟล์จริงแล้ว

ทดสอบกับแพตช์จริงตัวแรกของโปรเจกต์ (`HMBN_Th.ppf` — Harvest Moon: Back to Nature)
ซึ่งทำมาจาก PPF-O-Matic 3.0:

| | |
|---|---|
| รูปแบบ | PPF3.0 · imagetype 0 (BIN 2352) · มี block check · ไม่มีข้อมูล undo |
| เรคคอร์ด | 23,898 รายการ · แก้ 2,602,875 ไบต์ |
| ช่วงที่แก้ | ตำแหน่ง 100,640 ถึง 153,936,048 |

`applyPPF` อ่านเรคคอร์ดจบพอดีไม่เหลือเศษ และแปะสำเร็จโดยไม่มี error (ใช้เวลา 1.4 วินาที)

**จุดที่ไฟล์จริงพิสูจน์ว่าจำเป็น:** ท้ายไฟล์มีบล็อก `@BEGIN_FILE_ID.DIZ` ต่อท้ายอยู่ 233 ไบต์
ถ้าไม่มี `findRecordsEnd()` คอยตัดออก โค้ดจะอ่านบล็อกนั้นเป็นเรคคอร์ดแล้วได้ offset
มหาศาลจนพัง — ตอนเขียนไม่รู้ว่าเจอบ่อยแค่ไหน แต่แพตช์จริงตัวแรกที่เจอก็มีเลย

## ผลที่ตามมา
- ต้องมีชุดไฟล์ทดสอบ (ต้นฉบับ + แพตช์ + ผลลัพธ์ที่ถูกต้อง) ครบทั้ง 3 รูปแบบ แล้วเทียบผลลัพธ์ทีละ byte
- ต้องตรวจ checksum ที่ฝังมาในไฟล์ BPS ด้วย ไม่ใช่แค่แปะทื่อๆ
