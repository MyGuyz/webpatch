# ADR-002 — ใช้ Supabase เป็นฐานข้อมูลและระบบ login

**สถานะ:** ตกลงแล้ว · 2026-08-20

## บริบท
ต้องการฐานข้อมูลเก็บรายการเกม/แพตช์/ความคืบหน้า/รายงานบั๊ก และต้องมีระบบยืนยันตัวตนสำหรับหน้า Admin โดยต้องฟรีและไม่ต้องผูกบัตรเครดิต

## ทางเลือกที่พิจารณา
| ทางเลือก | ข้อดี | ข้อเสีย |
|---|---|---|
| **Supabase** | Postgres + ระบบ login + ที่เก็บไฟล์ครบในตัว, มีหน้าแก้ข้อมูลสำเร็จรูปให้ใช้ทันที | ที่เก็บไฟล์ฟรีแค่ 1GB, ข้อมูลขาออกเดือนละ 5GB |
| Cloudflare D1 | อยู่เจ้าเดียวกับที่โฮสต์ | ไม่มีระบบ login ให้ ต้องเขียนเอง, ไม่มีหน้าแก้ข้อมูลสำเร็จรูป |

## การตัดสินใจ
ใช้ **Supabase**

## เหตุผล
- มีระบบ login มาให้พร้อม ไม่ต้องเขียนเอง ซึ่งเป็นส่วนที่พลาดแล้วอันตรายที่สุด
- **หน้าแก้ข้อมูลสำเร็จรูปใช้ได้ตั้งแต่วันแรก** ทำให้ใส่ข้อมูลเกมได้ทันทีโดยไม่ต้องรอหน้า Admin เสร็จ (เป็นฐานของแผนเฟส 1)
- ข้อจำกัดเรื่องที่เก็บไฟล์แก้ด้วย ADR-003 (ไฟล์แพตช์ไม่เก็บที่นี่) เหลือแค่รูปภาพซึ่งเล็กมาก

## ผลที่ตามมา
- ต้องระวังไม่ให้ไฟล์ใหญ่หลุดเข้า Supabase Storage ไม่งั้นโควต้าขาออกหมดเร็ว
- ต้องตั้ง Row Level Security ให้ถูก เพราะกุญแจฝั่งหน้าเว็บเป็นของเปิดเผย
