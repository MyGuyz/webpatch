# พาตั้งค่าทีละขั้น — จากโค้ดในเครื่องสู่เว็บที่เปิดได้จริง

ใช้เวลาประมาณ 20–30 นาที ทำครั้งเดียวจบ ไม่ต้องใช้ command line เลย

ต้องมี: บัญชี GitHub · บัญชี Supabase · บัญชี Cloudflare (ทั้งหมดฟรี ไม่ต้องผูกบัตร)

---

## ช่วง A — Supabase (สร้างฐานข้อมูล)

เป้าหมายของช่วงนี้: **ได้ค่ามา 2 ตัว** เอาไปใช้ต่อในช่วง B

### A1. สร้างโปรเจกต์

1. เข้า [supabase.com/dashboard](https://supabase.com/dashboard) → กด **New project**
2. กรอก:
   - **Name** — ตั้งชื่ออะไรก็ได้ เช่น `webpatch`
   - **Database Password** — กดปุ่มสุ่มแล้ว **เก็บไว้ที่ปลอดภัย** (จะไม่ได้ใช้ในคู่มือนี้ แต่หายแล้วยุ่ง)
   - **Region** — เลือก **Southeast Asia (Singapore)** เพราะใกล้ไทยที่สุด เว็บจะเร็วกว่า
3. กด **Create new project** แล้วรอประมาณ 2 นาที

### A2. สร้างตาราง

1. เมนูซ้าย → **SQL Editor** (ไอคอนคล้ายกระดาษมีตัวอักษร `>_`)
2. กด **New query**
3. เปิดไฟล์ [`supabase/migrations/0001_initial_schema.sql`](../supabase/migrations/0001_initial_schema.sql) ใน repo นี้
   → **คัดลอกทั้งไฟล์** เอาไปวางในช่อง
4. กด **Run** (หรือ Ctrl+Enter)
5. ต้องขึ้น **Success. No rows returned** — ถ้าขึ้นแดงให้ดูหัวข้อแก้ปัญหาท้ายหน้า

### A3. เช็คว่าสำเร็จจริง

เมนูซ้าย → **Table Editor** → ต้องเห็นตาราง `announcements`, `bug_reports`, `changelogs`,
`consoles`, `games` ครบ 5 ตาราง และในตาราง `consoles` ต้องมีข้อมูลเครื่องเล่น 5 แถวอยู่แล้ว

### A4. คัดลอกค่า 2 ตัว

1. เมนูซ้าย → **Project Settings** (ไอคอนฟันเฟือง) → **API keys** หรือ **Data API**
2. คัดลอกเก็บไว้:

| ต้องหาอันไหน | หน้าตาประมาณนี้ |
|---|---|
| **Project URL** | `https://xxxxxxxxxxxx.supabase.co` |
| **anon public** key | สายอักษรยาวมาก ขึ้นต้นด้วย `eyJ...` |

> ⚠️ **ห้ามหยิบ `service_role` key เด็ดขาด** — มันข้ามระบบความปลอดภัยทั้งหมด
> ถ้าหลุดออกไปคนอื่นลบข้อมูลเราได้หมด ตัวที่ต้องใช้คือ **anon public** เท่านั้น
> (ตัวนี้เปิดเผยได้ ปลอดภัยเพราะมีกฎ RLS ในไฟล์ SQL คุมอยู่)

## ช่วง B — Cloudflare (เอาเว็บขึ้นออนไลน์)

### B1. เชื่อม GitHub

1. เข้า [dash.cloudflare.com](https://dash.cloudflare.com) → เมนูซ้าย **Workers & Pages**
2. กด **Create** → เลือกแท็บ **Import a repository**
3. กด **Connect GitHub** → อนุญาตให้ Cloudflare เห็น repo `MyGuyz/webpatch`
4. เลือก repo `webpatch` → กด **Begin setup**

### B2. ตั้งค่า build

| ช่อง | ใส่อะไร |
|---|---|
| Project name | `webpatch` (หรืออะไรก็ได้ — จะกลายเป็นชื่อเว็บ `ชื่อนี้.workers.dev`) |
| Production branch | **`main`** |
| Build command | `npm run build` |
| Deploy command | `npx wrangler deploy` |

### B3. ⚠️ ขั้นที่คนพลาดกันมากที่สุด — ใส่ตัวแปร

ในหน้าเดียวกัน หา **Environment variables** หรือ **Build variables** แล้วเพิ่ม 2 ตัว:

| ชื่อตัวแปร | ค่า |
|---|---|
| `PUBLIC_SUPABASE_URL` | Project URL จากขั้น A4 |
| `PUBLIC_SUPABASE_ANON_KEY` | anon public key จากขั้น A4 |

> 🔴 **ต้องใส่ในช่องของฝั่ง build เท่านั้น**
>
> Cloudflare มีช่องใส่ตัวแปร 2 ที่ คือ **ตอน build** กับ **ตอนเว็บทำงาน (runtime)**
> เว็บเราฝังค่าพวกนี้ตั้งแต่ตอน build ถ้าไปใส่ช่อง runtime **เว็บจะขึ้นได้ปกติ
> แต่ยังเป็นโหมดตัวอย่างตลอดไป และจะไม่มี error อะไรบอกเลย**
>
> ถ้าไม่แน่ใจว่าช่องไหน ใส่ทั้งสองที่ไปเลยก็ได้ ไม่เสียหาย

### B4. กด Deploy

กด **Save and Deploy** แล้วรอ 2–4 นาที เสร็จแล้วจะได้ลิงก์ `https://webpatch.xxx.workers.dev`

## ช่วง C — ตรวจว่าใช้ได้จริง

### C1. เปิดเว็บ

เปิดลิงก์ที่ได้ — **ต้องไม่มีกล่องสีเหลืองเขียนว่า "โหมดตัวอย่าง"**

- ยังเห็นกล่องเหลืองอยู่ → ใส่ตัวแปรผิดช่อง กลับไปทำ **B3** ใหม่แล้ว deploy ซ้ำ
- ขึ้น error 500 → ใส่ตัวแปรมาแค่ตัวเดียว เว็บจะบอกเองว่าขาดตัวไหน

### C2. หน้าแรกว่างเปล่า — ปกติ

เพราะยังไม่มีเกมในฐานข้อมูล มาใส่เกมแรกกัน

### C3. ใส่เกมแรก

กลับไป Supabase → **Table Editor** → ตาราง `games` → **Insert row**

ช่องที่ต้องกรอก:

| ช่อง | ใส่อะไร |
|---|---|
| `console_id` | ดูเลข id จากตาราง `consoles` (เช่น Super Famicom = 1) |
| `slug` | ชื่อภาษาอังกฤษไม่มีเว้นวรรค เช่น `bahamut-lagoon` (ห้ามซ้ำกับเกมอื่น) |
| `title` | ชื่อเกม |
| `status` | `ready` ถ้าแพตช์เสร็จแล้ว · `wip` ถ้ายังทำอยู่ |
| `patch_url` | ลิงก์ไฟล์แพตช์บน GitHub Releases |
| `patch_format` | `ips` หรือ `bps` หรือ `ppf` |
| `source_sha1` | ลายนิ้วมือไฟล์เกมต้นฉบับ — หาค่าได้ที่หน้า `/tools/sha1` บนเว็บ (เว้นว่างได้ = ไม่ตรวจรุ่น) |
| `is_published` | ✅ **ติ๊กให้เป็น true ไม่งั้นเว็บจะไม่แสดง** |

> เกมที่ `status` เป็น `ready` **ต้องมี** `patch_url` และ `patch_format`
> ไม่งั้นฐานข้อมูลจะปฏิเสธ (กันไม่ให้ผู้ใช้กดแล้วเจอหน้าเปล่า)

### C4. เปิด repo เป็นสาธารณะ (ทำครั้งเดียว)

ไฟล์แพตช์ใน repo ส่วนตัว **คนอื่นโหลดไม่ได้** เว็บจะขึ้น error ตอนกดแปะ

repo → **Settings** → เลื่อนล่างสุด **Danger Zone** → **Change visibility** → **Make public**

### C5. เอาไฟล์แพตช์ขึ้น GitHub

1. ไปที่ repo → ขวามือหา **Releases** → **Create a new release**
2. **Choose a tag** → พิมพ์ tag ใหม่ เช่น `bahamut-v1.3` → **Create new tag**
3. ลากไฟล์แพตช์มาวางในช่อง **Attach binaries**
4. กด **Publish release**
5. คลิกขวาที่ไฟล์ที่แนบ → **Copy link address** → เอาไปใส่ช่อง `patch_url` ในขั้น C3

### C6. ลองใช้จริง

เปิดหน้า **แปะแพตช์** บนเว็บ → เลือกเกม → เลือกไฟล์เกมต้นฉบับ → กดแปะ → ดาวน์โหลด
เอาไฟล์ที่ได้ไปเปิดในอีมูเลเตอร์ดูว่าเป็นภาษาไทยจริงไหม

## เจอปัญหาแบบนี้ แปลว่าอะไร

| อาการ | สาเหตุ | แก้ยังไง |
|---|---|---|
| เว็บขึ้นกล่องเหลือง "โหมดตัวอย่าง" | ใส่ตัวแปรผิดช่อง หรือยังไม่ได้ใส่ | ทำ **B3** ใหม่ แล้ว deploy ซ้ำ |
| เว็บขึ้น error 500 | ใส่ตัวแปรมาแค่ตัวเดียว | ดูข้อความบนหน้าจอ มันบอกเองว่าขาดตัวไหน |
| หน้าแรกว่าง ทั้งที่ใส่เกมแล้ว | ลืมติ๊ก `is_published` | ไปติ๊กในตาราง `games` |
| กดแปะแล้วขึ้น "ยังไม่มีไฟล์แพตช์" | `patch_url` ว่าง | ทำ **C5** |
| กดแปะแล้วขึ้น "ต้นทางไม่สำเร็จ (404)" | repo ยังเป็น private | ทำ **C4** |
| กดแปะแล้วขึ้น "ที่อยู่ไฟล์แพตช์ไม่ถูกต้อง" | ลิงก์ไม่ได้ชี้ไป GitHub | ต้องเป็นลิงก์ GitHub เท่านั้น ตั้งใจกันไว้เพื่อความปลอดภัย |
| กดแปะแล้วขึ้น "ไม่ตรงรุ่น" | ไฟล์เกมคนละเวอร์ชันกับที่แพตช์รองรับ | ถูกแล้ว ระบบกันไว้ไม่ให้ได้ไฟล์เสีย |
| SQL ขึ้นแดงว่า `already exists` | รันไฟล์ SQL ซ้ำ | ไม่เป็นไร ตารางสร้างไปแล้ว ข้ามไป **A3** |
| Cloudflare build ไม่ผ่าน | ดู log ในหน้า deployment | ส่งภาพหน้าจอมาถามได้ |

## เพิ่มเกมครั้งต่อไปทำยังไง

ตอนนี้ยังต้องทำ 2 ที่: อัปไฟล์ที่ GitHub Releases (**C5**) แล้วมากรอกข้อมูลที่ Supabase (**C3**)

หน้า Admin ที่จะทำให้เหลือ **ฟอร์มเดียวจบ** อยู่ในแผนเฟสถัดไป
